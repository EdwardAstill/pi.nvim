1. INTRODUCTION                                             *pi-introduction*

pi.nvim is the Pi-specific glue between CodeCompanion, codecompanion-ui,
pi-acp, and mini.diff.

  CodeCompanion -> ACP -> pi-acp -> Pi RPC

CodeCompanion owns chat, streaming, tool display, sessions, models, and editor
context. codecompanion-ui owns the editable composer. pi.nvim owns project
association, pre-submit Git-tree checkpoints, and acceptance semantics. There
is no terminal frontend or fallback.

==============================================================================
2. REQUIREMENTS                                             *pi-requirements*

  - Neovim >= 0.11
  - Node.js >= 22 and Pi >= 0.80.4
  - git, pi, and pi-acp executables
  - olimorris/codecompanion.nvim
  - mrjones2014/codecompanion-ui.nvim
  - nvim-mini/mini.diff

Install Pi and pi-acp: >sh

  npm install -g @earendil-works/pi-coding-agent pi-acp

3. SETUP                                                           *pi-setup*

Register the Pi ACP adapter and enable codecompanion-ui in CodeCompanion: >lua

  require("codecompanion").setup({
    adapters = {
      acp = {
        pi = function()
          return require("pi.codecompanion").adapter()
        end,
      },
    },
    extensions = {
      ui = { enabled = true },
    },
  })

  require("pi").setup({
    codecompanion = {
      adapter = "pi",
      command = { "pi-acp" },
    },
    compatibility = {
      legacy_context_tokens = true,
    },
    project = { cwd = nil },
    review = {
      enabled = true,
      save_before_prompt = true,       -- required; false is rejected
      overlay = true,
      keymaps = {
        previous_hunk = "[h",
        next_hunk = "]h",
        accept_hunk = "a",
        reject_hunk = "r",
        accept_file = "A",
        reject_file = "R",
        close = "q",
      },
    },
    keymaps = {
      toggle = "<leader>pt",
      ask = "<leader>pa",
      select = "<leader>px",
      prompt_this = "<leader>pp",
      abort = "<leader>pq",
    },
    events = { reload = true },
  })
<

Use `{ "npx", "-y", "pi-acp" }` as the command if pi-acp is not globally
installed. Passing the removed `terminal` option is an error.

4. COMMANDS                                                   *pi-commands*

                                                               *:Pi*
  :Pi, :Pi toggle       Show or hide the project chat
  :Pi focus             Focus the codecompanion-ui composer
  :Pi ask [text]        Open the composer with optional text
  :Pi prompt {text}     Submit text or a configured prompt name
  :Pi select            Select a configured prompt or control
  :Pi abort             Abort the current Pi request
  :Pi model             Open CodeCompanion's model selector
  :Pi thinking          Open CodeCompanion's ACP thinking selector
  :Pi checkpoint        Capture a manual turn baseline
  :Pi review            Review changes against accepted_tree
  :Pi review turn       Audit changes against turn_base_tree
  :Pi review session    Audit changes against session_start_tree
  :Pi accept hunk       Accept the current hunk
  :Pi accept file       Accept the current file
  :Pi accept all        Accept all pending files
  :Pi reject hunk       Reject the current hunk
  :Pi reject file       Reject the current file
  :Pi status            Show checkpoint/review status
  :Pi stop              Close the project chat and ACP process

The default global keymaps are `<leader>pt`, `<leader>pa`, `<leader>px`,
`<leader>pp`, and `<leader>pq`. Set any configured keymap to `false` to remove
it. Hiding the UI does not stop Pi.

5. CHECKPOINTS AND REVIEW                                       *pi-review*

Before CodeCompanion submits each Pi prompt, pi.nvim synchronously saves
modified project buffers and captures `turn_base_tree`. A failure cancels the
submission and the composer draft is restored.

The first project snapshot initializes `session_start_tree` and mutable
`accepted_tree`, including pre-existing working-tree changes.

  pending   compares accepted_tree to the worktree; mutable
  turn      compares turn_base_tree to the worktree; audit only
  session   compares session_start_tree to the worktree; audit only

Accepting advances only the private accepted tree. Rejecting restores accepted
content into the worktree. A temporary Git index is used. pi.nvim never changes
the real index, stages files, or creates commits or branches.

Pending mappings are `[h`, `]h`, `a`, `r`, `A`, `R`, and `q`. They exist only
in an attached review buffer. Deleted, binary, symlink, and unsupported files
use file-level accept/reject.

6. CONTEXT                                                     *pi-context*

CodeCompanion editor context is canonical. Useful references include
`#{selection}`, `#{buffer}`, `#{buffers}`, `#{viewport}`, `#{diagnostics}`,
`#{quickfix}`, and `#{diff}`.

For one compatibility release, pi.nvim textually translates `@this`,
`@buffer`, `@buffers`, `@visible`, `@diagnostics`, `@quickfix`, and `@diff`.
The removed pi.context module does not capture or render context.

==============================================================================
7. API                                                           *pi-api*

  require("pi").setup(opts)        Configure integration and hooks
  require("pi").toggle()           Show or hide the project chat
  require("pi").focus()            Focus the composer
  require("pi").ask(text, opts)    Open a draft; opts.submit sends it
  require("pi").prompt(text, opts) Submit text or a prompt name
  require("pi").select()           Open the prompt/control selector
  require("pi").abort()            Abort the current request
  require("pi").model()            Delegate model choice to CodeCompanion
  require("pi").thinking()         Delegate thinking choice to CodeCompanion
  require("pi").checkpoint()       Capture a manual turn baseline
  require("pi").review(scope)      Open pending/turn/session review
  require("pi").accept(target)     Accept hunk/file/all
  require("pi").reject(target)     Reject hunk/file
  require("pi").status()           Return and display review status
  require("pi").stop()             Close the project chat/process

==============================================================================
8. HEALTH                                                       *pi-health*

Run `:checkhealth pi`. The check reports Neovim, pi, pi-acp, git,
CodeCompanion, codecompanion-ui, mini.diff, project root, and setup status.
